- Land work package WP2 of the 2.3 candidate ([ADR 0022](docs/decisions/0022-values-places-and-expressions.md) B3, [ADR 0024](docs/decisions/0024-communication-and-package-links.md) B15 and B16).
  - The whole-expression conditional `if (c) a else b`: the right side of an assignment or declaration, an argument, a return value, an assertion, a guard, an index or a parenthesized operand (`x = 1 + (if (c) 2 else 3) + 4;`); `else if` chains and `else` extends to the end. It is never a statement: `if (c) g() else h();` is a syntax error that explains the if block, and an unparenthesized operand is a syntax error that explains the parentheses. The condition is `bool`; the type is the common type of the branches under scalar widening, records, enums and arrays identical, no void branch (SW2002); no suspending call anywhere inside (SW2006); its effect is the union of condition and both branches; only the selected branch is evaluated. KerML: `ControlFunctions::'if'`.
  - `view`, `state`, `in` and `out` are contextual words, legal names in every name position next to their keyword roles. `formatName`, `formatQualifiedName` and `formatPath` take an optional edition and write the words unquoted for 2.3, quoted for 2.2; `reservedWords(edition)`, `RESERVED_WORDS_2_2` and `CONTEXTUAL_KEYWORDS_2_2` are new exports of `names`. Diagnostics keep spelling names in the 2.2 quoting (`MESSAGE_SPELLING`), so 2.2 sources keep their messages byte for byte; the name functions treat a non-string edition (such as the index argument of `map`) as the default, and `namesFor(edition)` binds them to one edition.
  - Association lists `associate a, b to 'X', 'Y';` associate every listed occurrence with every listed case; each pair follows the existing rules at its listed reference; a repeated pair is SW2010 `{occurrence} is already associated with {case}.` at the later reference (two single statements keep the 2.2 message). `Association` gains `moreOccurrences` and `moreTargets`; `associationPairs`, `associationOccurrences`, `associationTargets` and `isAssociationList` in `semantic` read every pair; projection links of a list carry `pair` positions. The formatter prints conditionals and wraps lists longer than 100 characters with one occurrence or case per line.
  - Examples 35 (conditional), 36 (contextual words) and 37 (association lists), each with cases.
  - Recovery: a conditional never starts with `if (…) {`, so an incomplete line typed above an if statement fails at `if` as in 2.2 and the statement list resynchronises. The binary chains from `or` down to `*` are written into `Expression` (the AST is unchanged), so a nesting level costs three parser rule calls instead of nine and bracket nesting parses deeper than in 2.2 on every form (in a fresh process 228 parentheses against 148, 205 indexes against 122); nested blocks keep the parser calls of 2.2 per level, and their deepest nesting can be about 4 to 5% lower, depending on the machine and the process state (compatibility exception X1 in the release draft).
  - Parser nesting limits (WP2-D05, SW2013): a statement with more than 200 brackets open at once (braces inside brackets and record-literal braces count), or one that ends with brackets unclosed after more than 32 were open, is reported and not parsed, and the rest of the file is parsed; the limit is above every depth 3.1.0 parses. A parse that still overflows the host stack (such as 1,200 unclosed blocks) reports SW2013 for its file instead of throwing. 800, 1,200 and 5,000 unclosed `a[` and 1,200 unclosed `f(record R { v =` fail in milliseconds; in 3.1.0 the first threw a stack overflow out of the document build and the last exhausted memory after 35 s.
  - Consumers: the CST node of a binary expression of any operator (`or`, `and`, comparisons, `+`, `-`, `*`, `/`, `%`) built at the top of an `Expression` has the grammar rule `Expression` (was `OrExpression` … `MultiplicativeExpression`). A consumer that recognises an operator by the CST grammar rule name (for example `grammarRule === 'OrExpression'`) must use the AST (`BinaryExpression.operator`) or the token instead. `LangiumParser.parse` no longer throws on a stack overflow; other exceptions still propagate.
  - Consumers: reading only `Association.occurrence`/`target` sees only the first pair of a list (use `associationPairs`); removing an associate statement removes every pair of its list; expression walkers must descend into `ConditionalExpression`; `RESERVED_WORDS` lost `view`, `state`, `in` and `out` (`reservedWords('2.2')` keeps them); new exports are listed in the release draft.

- Land work package WP5 of the 2.3 candidate ([ADR 0023](docs/decisions/0023-state-reactions.md) B7 to B10): state reactions.
  - Completion transitions `when (g) to S { … }`: guard-only, evaluated in declaration order after the entry actions of a state finish and after every internal reaction, never after a discard; the guard is pure or reads state and never calls `now()`; a cycle of `when (true)` transitions is an error; reachability includes completion edges. This reverses the 2.0 exclusion of completion transitions for guard-only completion.
  - Guarded timers `after D when (g) …`: a false guard consumes the timer for this state entry (`discardTimer`), the next timer with the same expiry is tried and later timers stay armed.
  - Internal transitions: a receive or timer transition without `to` runs only its effect, without exit, entry or state update; the timers keep their epoch, an internal timer fires once per entry, and the trace records a `state` observation with `internal: true`. Explicit self transitions keep their 2.2 meaning.
  - Deferral `defer p.m, …;` in a state: input for a deferred member stays in its connection queue with its policy (capacity, overflow, `maxAge`, latest attribute), one `defer` observation per retained message, at its first retention, whether the machine waits or runs an action of the deferring state; a state that handles retained members consumes them before other input, in global offer-ordinal order across the machine's queues; a state that neither handles nor defers them discards them (`inactiveOwner`). A deferral is part of the machine's single input ownership (SW2005).
  - The selection order of a state: completion, elapsed timers, retained input, other input in the 2.2 order. A completion chain that re-enters a state within one instant without consuming input or a timer and without a suspension is the contract violation `CompletionLoop` (subject the machine, source the completion transition), which fails a case; a retry whose entry suspends on a request is allowed. A machine without the new forms runs exactly as in 2.2.
  - Diagnostics: SW2008 messages for the new forms (chapter 4.4); SW2017 (warning) for a completion guard that reads nothing the machine writes; SW2018 (warning) for a deferred event whose route into the occurrence rejects on overflow. Both are impossible on 2.2 sources.
  - `defer` is a contextual word: a keyword only at the start of a state member and a basic name in every edition, so no 2.2 spelling or message changes. An unclosed reaction block ends at the next state member, state or final state and is reported as missing its `}`, so the following transitions, deferrals and states are kept (a 2.2 parse-error source with an unclosed block at the end of a state keeps its next state again, as in 2.2). The SW2000 expected-token lists of parse errors also name `defer` where a state member can start.
  - Projections: completion edges labelled `when (g)` with `completion: true`, guarded timer edges with `guard`, internal transitions as state `reactions` without an edge, `deferrals` on state nodes; absent on 2.2 sources. The formatter prints the new forms; rename and references cover deferred members; the KerML inventory maps `Deferral` as a lowering.
  - Examples 44 (session completion), 45 (lock deferral) and 46 (breaker with internal transitions), each comparing a 2.2 shape with the 2.3 form in mutation-checked cases, and 47 (every reaction form in one machine, for the warning-free grammar gate). Example 43 gains a literal period with a computed deadline, and its expected Deadline failure is pinned by a `runs.json` entry (`expectedMessage`, new in `scripts/check-simulations.mjs`).
  - Consumers: `Transition.target` is optional (an internal transition has none, a completion transition no trigger); `State.deferrals` and `Deferral` are new; new trace kinds `defer` and `discardTimer`, `state.internal`, `violation.source` for `CompletionLoop`; see the WP5 consumer notes in [the 2.3 release draft](docs/RELEASE_2_3.md).
- Land work package WP6 of the 2.3 candidate ([ADR 0024](docs/decisions/0024-communication-and-package-links.md) B13, B14): sampled reads and member policies.
  - Sampled reads `p.m`: a port whose attribute members declare an initial value (`provides attribute ajar: bool = false;`) opts in; a component then reads the latest value delivered to a required attribute of it, in operation bodies and in receive, completion and timer guards. The sampling side's initial value is mandatory (SW2004); the initial value is pure and typed like an attribute initializer. Sampling is not ownership: a sampled member has zero or one consuming owner. Not allowed on a forwarded boundary (SW2005), in initializers (SW2006), in period and deadline expressions (SW2007) or in case scripts (SW2010). `p.m` on a port that does not opt in keeps its 2.2 diagnostics.
  - Sample cells: initialized to the initial value before startup, updated at each delivery instant after latency and fault delay, independent of consumption, never by a dropped offer or a value older than `maxAge`; read live by serial and concurrent activations, and stable within an activation until it suspends. Each update is a new `sample` observation; an unconsumed sampled member has no queue and no `deliver`.
  - Member policies `connect bodyCan: Cyclic (bcm.bus, dcu.canBus) { crash: CanEvent; }`: the effective policy of a member route is its member policy, else the connection policy, else Default, for capacity, overflow, ordering, delivery, request timeout, latency and age; SW2013 idempotency and SW2018 apply per member route; not on forwarding, members of both ports, once per member (SW2004); `redefines connect` replaces them all.
  - SW2017 revisited: a completion guard that reads only sample cells warns (completion is not re-evaluated on a cell update), and a completion guard that folds to false now warns that its transition is never taken (owner decision on the WP5 review). The polling exemption counts only a self receive or timer transition, or an internal receive, that can fire, and only for a guard on an attribute some operation writes or on a sample cell.
  - Projections: `ProjectionEdge.memberPolicies`, `ProjectionNode.sampled` and the `initial` text of port members, absent on 2.2 sources. The formatter prints member-policy bodies and initial values; the KerML inventory maps `MemberPolicy` as a reference.
  - Examples 48 (door status sampling, against the 2.2 store handlers) and 49 (body CAN member policies), with mutation-checked cases.
  - Consumers: `PortMember.initial`, `Connect.memberPolicies` and `MemberPolicy` are new; a dotted reference can be a sampled read; route policies are per member; see the WP6 consumer notes in [the 2.3 release draft](docs/RELEASE_2_3.md).

- Land work package WP4 of the 2.3 candidate ([ADR 0022](docs/decisions/0022-values-places-and-expressions.md) B6): durations as values.
  - A duration literal is a `uint` value in nanoseconds in any expression (`5ms` is 5000000; `0ms` is 0 there, while the 2.2 positions still require a positive literal). The unit words stay names.
  - Computed waits `wait (e);` and receive timeouts `or after (e) { … }` take an integral expression without suspending calls, evaluated when the statement starts waiting. Computed state timers `after (e) to S { … }` are pure or read state and are evaluated once per state entry when the entry actions finish, expiring at the state-update time plus the value, so a Backoff state that doubles its delay on entry waits the new delay. A value that is not positive or not a representable duration, including integer overflow of the duration arithmetic, is the runtime failure `DurationRange`, which `try` catches; `ClockRange` is unchanged.
  - Computed periods `on every (e)` and deadlines `deadline (e)` use the constant sublanguage (literals, const attributes with their effective value per occurrence, arithmetic with exact integral division, comparisons, `and`/`or`/`not`, the conditional; no calls, mutable state or `now()`), evaluated for every expanded occurrence of every top-level occurrence by one evaluator, `constantValue`: per-occurrence SW2013 for non-positive or unrepresentable values and non-exact divisions, SW2007 for a deadline above its period and for expressions outside the sublanguage. Trigger identity is the canonical expression text, so `every (20ms)` is `every 20ms`.
  - `PolicySetting` has the single form `name = Expression;`; `requestTimeout`, `maxLatency` and `maxAge` are duration literals and no other setting is a duration (`capacity = 5ms;` stays invalid with its 2.2 message).
  - SW2016 (warning): a computed duration without a unit counts nanoseconds; multiply by a unit such as `1ms`. SW2019 (warning, rule WP4-D08, added in the review, so the draft rule count becomes 210): two `every` entries of one occurrence for the same operation with equal periods but different triggers, which do not replace each other.
  - Traces: computed waits and timeouts add `durationNs`; computed state timers add a `timer` observation with `timerNs` and `expiresNs`; literal forms add nothing.
  - Projections: per-occurrence `periodNs`/`deadlineNs` for computed entries and `periodExpression`/`deadlineExpression` with the canonical text; a computed timer labels its transition `after (e)`. The formatter prints computed durations in parentheses.
  - Examples 41 (computed backoff), 42 (lock pulse) and 43 (derived period), each with cases.
  - Consumers: `PolicySetting.duration` is removed (use `settingDuration`) and `PolicySetting.value` is required; `Duration.$container` no longer includes `PolicySetting`; `Wait.duration` is optional; `Literal.duration`, `Wait.delay`, `Receive.timeoutValue`, `ScheduleEntry.periodValue`/`deadlineValue` and `Transition.delayValue` are new; read periods and deadlines per occurrence with `entryPeriod` and `entryDeadline` and trigger identity with `triggerIdentity`; the full list is in the release draft.

### Reference implementation (not part of the standard)

- Report an expression nested more than 1,000 levels deep (for example a sum of more than 1,000 terms) with SW2013, the reference validation limit, instead of failing validation with a stack overflow; such an expression is not type-checked or run, and splitting it into local variables avoids the limit. Sources nested several thousand levels deep still exceed the stack of the Langium parser itself.
- Run `swaml test` cases one at a time. runTests held every case's complete run, trace included, until the last case finished, so a model with many long cases could exhaust the default V8 heap. The new eachTest yields one case result at a time (runTests returns the same results); text output keeps only each verdict, and JSON output keeps each case's serialized text and writes the cases array piece by piece with the same bytes as before. Twelve 5 s cases with a 1 ms period now run in a 48 MB heap, where holding every run needed more than 64 MB. A single case's run still keeps its whole trace, which the JSON report contains.
- Let one example run its cases with its own simulation options. examples/simulation/cases.json keeps its global options and may add modelOptions, mapping an example to options such as maxSteps or untilNs that override the global ones for that example only; the file is checked by the simulator's own option validator, now exported as simulationOptionsProblem, so the two cannot drift: unknown options, values of the wrong type or range, fault offers below 1 or repeated and unknown keys inside a fault are rejected (the simulator now also rejects unknown fault keys), as are unknown file keys, models that are not complete examples and options for an example without cases. scripts/simulation-cases.mjs documents the file; the maintained guides are unchanged because the published 2.2 reference embeds them. The example gate also pins every documented example warning by file, code and position, so a new or vanished warning fails it.
- Explain an ambiguous short name. A use case or test named like an imported requirement, or two imported declarations sharing a name, made a reference unresolvable with the misleading SW2001 "Could not resolve reference" message. The SW2001 diagnostic now names every declaration that shares the name, with its kind, package and whether it is imported, suggests only qualified names that resolve to one declaration of the expected kind (otherwise renaming) and lists the declarations, in canonical spelling, as related information. Resolution itself is unchanged: ambiguous short names remain errors and qualified names resolve.
- Make the SW2011 stale-read warning follow its rule, a pre-suspension state read that may affect a later write, instead of any attribute read followed anywhere later by any suspension and any attribute write. It now follows values through locals, operands, out arguments and conditions in execution order: a suspension (wait, receive, an interrupt handler, a request or a suspending call) makes earlier reads stale, a read after resuming is fresh, and an `if` whose branch returns or fails guards the rest of its block. A write is reported when its value is stale, or when a stale condition guards it and no condition evaluated after resuming reads again either every attribute that condition read or every attribute the write depends on (its value's attributes and the written attribute). Out-argument targets are written, not read. Calls to the component's operations are followed with the caller's argument values and conditions, so moving the write into a helper no longer hides it; the warning is then reported at the call. One state machine reaction is analysed as the source state's exit action, the transition effect and the target state's entry action under the guard, with the initial entry on its own; an interrupt handler starts from the join of every suspension in its protected body. Each operation is summarised once per validation pass in terms of its parameters and its caller's conditions and every call site instantiates that summary; a helper's own stale write and a different write its caller makes stale are both reported. Loops run to a fixed point. Summaries decide a helper's own findings per write, then record the other writes by their stale inputs and conditions with the set of attributes written that way, so a helper assigning hundreds of attributes stays small (tests compare the merged summaries with an unmerged reference on 250 random helper/caller models and on 100 models of two sibling writes under re-checked conditions, the family that, with own findings judged after merging, loses 14 caller warnings); beyond 64 distinct conditions the call-site dependent records merge into one conservative record that keeps every finding. The analysis has a reference validation limit of 200,000 statement visits per document; past it, one SW2013 warning on the name of the operation where it stopped says that SW2011 is not checked for that operation and the operations validated after it, instead of claiming a stale read. The effects of operations are computed once per call graph and cached for a validation pass, and the recursion check visits each callee once, so deep call graphs with shared callees no longer take exponential time (the reviewer's depth-12 chains took 1.4 s to 143 s, depth 20 now validates in under 100 ms). The code, message, severity and identity metadata are unchanged; the range is the reported assignment or call.
- Fix `swaml --format` losing documentation and comments. On Node.js 26.12.0, V8's Maglev on-stack replacement of the formatter loop intermittently lost a write to a closure-captured line buffer, so a large file lost `/** */` and `//` comments from some point on (50 of 154 docs in one run of the door controller showcase) and `--check-format` flapped; Node.js 24, `--no-maglev` and `--no-use-osr` were unaffected. The formatter keeps its state in an object, and every result is verified before it is returned: each token, comments and documentation included, must appear in order with its exact text separated only by whitespace, no other non-whitespace character may change, and the result must lex to the same token stream. The re-lex uses the language's own lexer when a host passes none, so `formatDocument(document)` is fully checked too. A failed check throws `FormattingSafetyError` and never writes: a host that catches it must keep the source unchanged and report the error, which indicates a formatter defect rather than a problem in the model; the CLI reports an `internal-error` diagnostic and exits 2, and the LSP formatter returns the error to the client instead of edits. Formatted text uses the source's dominant line ending (CRLF when most line breaks are CRLF, otherwise LF) for every line, including inside multi-line comments; previously every output line ended with LF. Layout fixes: array literals are spaced like values (`return [a, b]`, `= [1, 2]`, `in [1, 2]`), a unary minus attaches to its operand (`-128`, `-(a)`), `when (` is spaced like `if (`, state actions and transitions after a closing brace start their own lines (only `else`, `or` and an interruptible handler continue it), and a leaf declaration's trailing documentation stays before its semicolon instead of leaving a lone `;`. Examples 03, 04, 05, 07, 08, 12, 13, 14, 18, 21, 30 and 31 are not in the canonical layout; they are unchanged because the published 2.2 reference and its manifest embed them.
- The public-content check also rejects local drive-letter paths and editor-product repository names, with its patterns in `scripts/public-content-rules.mjs` and a CI test. No standard, grammar, API or implementation version change.
- Make model projection and simulation scale with the model and the run instead of their square, with identical results. projectModel indexes candidate paths once to find each owner, so the 1,800-line benchmark model with 5,600 projected nodes projects in milliseconds instead of seconds; a workspace with an unnamed package, while one is being typed, keeps the previous search and its results. The interpreter keeps pending events in a binary heap ordered by time, phase and scheduling order, skipping and compacting events whose activation, wait or request already ended, and keeps only uncompleted activations for dispatch, input and limit checks, so a step no longer costs time for every earlier event and activation. Simultaneous events keep their phase and scheduling order; projections, traces, ordinals, stores, statuses, failures and case results are unchanged in every compared model. npm run bench measures projection and simulation scaling, and scripts/bench/differential.mjs compares this build with another revision over the examples and generated and seeded random models. No standard, grammar, API or implementation version change.
